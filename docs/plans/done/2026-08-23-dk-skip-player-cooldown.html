Implementation Plan · 2026-08-23

Player-wide weekly cooldown for ندیدمش skips

Planning 0 / 0 tasks 0 / 0 steps TDD

Architecture

The 🤷 ندیدمش tap means "I have not seen this person play", but the queue treats it as a per-indicator dedupe scoped to the active session, so the same player immediately comes back under a different skill. This plan makes a skip suppress the whole player for that voter for a rolling cooldown window (SKIP_COOLDOWN_DAYS, default 7) instead of one (player, indicator) pair for one session. The row shape in score_skips is unchanged, so dont_know_stats and the DK alert keep working; the exclusion predicate changes in voting_queue.select_next_score_target, its mirror in handlers/health.py, and the ghost-merge copy in players.py that would otherwise re-arm every migrated skip.

Rationale

This is the actual bug. `ندیدمش` is a statement about the person ("I have not seen them play"), so scoping the suppression to one indicator guarantees the voter is asked about the same person five more times.

Risks
  • Use the `'-' || :cooldown_days || ' days'` concatenation form with an int bind, NOT `datetime('now', :cooldown)` with a pre-formatted string. If the latter is ever fed an int, `datetime()` returns NULL, `skipped_at > NULL` is never true, and every skip is silently ignored — the bug returns with no error and no failing test.
  • `skipped_at` is written with `CURRENT_TIMESTAMP`, which SQLite stores in UTC; `datetime('now', ...)` is also UTC, so the comparison is consistent. Do NOT switch either side to `localtime`.
  • Removing the `session_id` parameter is a signature change — tests/test_voting_queue.py:54 and handlers/voting.py must be updated or the suite fails on unexpected-kwarg errors.
